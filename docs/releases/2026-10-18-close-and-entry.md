# 合书回卷与详情挂载优化 — 2026-10-18

## 行为

- 合书改为两段：已翻过的书页先依序回卷归位，封面保持打开；全部落位后再合上封面并恢复书架姿态。修复翻很多页后合书时，封面与书页绕同一书脊同时扫过、在投影上互相穿插的问题。
- 回卷起始间隔封顶 0.36 s，封面至少保留 0.42 s 摆动；常规 1–4 页的合书总时长仍约 1.02 s，最深页合约 1.22 s，不再出现封面突然盖过仍在翻转的页。
- 详情页首次挂载时，首屏条目立即挂载 Tiptap 编辑器；其余条目先以同版式静态正文渲染，再按每批 2 条、间隔 16 ms 升级为可编辑。正文内容不变，避免一次提交创建十余个编辑器造成的长任务。
- 减少动态效果偏好下，合书与编辑器的分批升级仍按既有即时路径完成。

## 验证

- `npm run typecheck`、`npm run build` 通过。
- Vitest：新增 5 项回卷顺序测试；全量 129 个文件、714 项通过、1 项跳过。
- 编辑器回归 29 项通过。
- Playwright 38 项通过，新增断言：回卷期间封面保持 `-180deg`，书页全部归位后才开始合封面。
- 真实帧（CDP screencast）核对合书：回卷阶段封面保持打开，落位后封面合上，无穿插。
- 生产构建 + 4× CPU 降速的详情进入（点击到静止）：长任务阻塞 76–101 ms（前一版 104–157 ms），最大帧 133–159 ms（前一版 167–217 ms），总时长约 1.33 s（前一版 1.66 s）。开发服务器回归场景由 271–406 ms 降至约 204 ms。
- 剩余单次长任务约 130–150 ms，主要是编辑器模块编译、首屏挂载与分页测量；不随页数增长。
- 未执行登录后的生产浏览器验收；生产仅核对 `/api/health`、前端资源与新增分包可访问。
