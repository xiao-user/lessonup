# 学习与教学连续性系统：统一落地方案

> 状态：实施中  
> 建立日期：2026-08-01  
> 作用：这是“平台知识网络、学期框架、单元规划、课时蓝图、正式教案与 Agent”建设的长期实施基线。后续变更必须在本文记录原因，不以临时对话替代产品决策。

## 一、产品目标

LessonUp 不是只帮助教师写一篇教案，而是要形成一条可追溯的教学决策链：

`教材目录 → 通用知识网络 → 学期教学框架 → 单元规划 → 课时蓝图 → 正式教案 → 课堂反馈 → 后续调整`

知识点及其关联不是最终目的。它们是系统判断“这节课应复习什么、为什么需要复习、应为后续什么内容做铺垫”的基础设施。最终产物必须落回可执行的教学设计，而不是停留在图谱展示或通用建议上。

## 二、16 项统一方案

### 1. 统一产品定义

建立“学习与教学连续性系统”。平台知识网络负责可复用的课程语义，教师规划负责结合学情、课时和教学目标做本地化决策，Agent 负责检索、解释、建议和生成草案，但不替代教师确认。

### 2. 核心业务闭环

先确定教材与学期范围，再形成整册/学期框架；以单元目标拆分课时主要活动；由前后知识依赖推导复习与铺垫；最后生成正式教案，并用课堂反馈修正后续计划。

### 3. 平台课程知识网络

依赖科目、学段/年级、教材版本、册次和目录节点。外部统一称为“知识点”；内部保留语义类型、认知层级、证据、审核状态和关系类型，以便 Agent 精确判断。网络首先是可检索基础设施，不以可视化关系图为优先目标。

### 4. Phase 0 架构边界

- 教材目录必须使用不可变发布版本。业务数据绑定 `catalog_release_id`，当前目录通过指针切换，历史记录不得被覆盖。
- Agent 必须具有明确资源作用域。第一阶段支持 `lesson_file` 和 `semester_framework`；线程、分支、运行、审批、补丁和版本都绑定同一资源。

### 5. 知识网络生产管线

目录定位 → 样本导入/AI 候选抽取 → 结构和证据校验 → 人工或规则审核 → 发布不可变语义版本。AI 产出默认为候选，不直接成为平台事实。

### 6. 学期框架数据模型

学期框架绑定教师/组织、教材目录发布版本和语义发布版本，包含教学周、可用课时、单元安排、课时蓝图、学情约束和版本。单元及课时规划保留来源、教师覆盖项和版本历史。

### 7. 确定性连续性引擎

先用目录顺序、相同知识点、已审核关系和显式先修/后继边生成候选，再由 Agent 结合学情解释：

- 前序出现或属于先修条件：候选为复习/巩固；
- 后序出现或依赖当前内容：候选为铺垫；
- 缺少证据时必须标注不确定，不伪造关联。

### 8. Agent 实现

保留一个对用户可见的备课管理 Agent，课程分析、教学设计、评价与批判能力作为内部工具。Agent 按需读取目录、知识点、关系、学期框架和教案，不把完整目录或知识网络注入提示词。所有写入都生成可审阅的资源补丁。

### 9. UI 信息架构

在现有备课本和教案流程中增加学期框架入口。默认呈现单元/课时序列、目标、主要活动、复习和铺垫原因；关系网络仅作为辅助探索视图。AI 建议、平台事实和教师决定必须有清晰视觉边界。

### 10. 备课方法映射

- 整册通读映射为学期框架与单元目标；
- 前后知识关联映射为复习/铺垫建议；
- 主要活动映射为课时蓝图；
- 做题找难点映射为题目、易错点和学情证据；
- 可测目标映射为能力表现与评价任务；
- 逐字稿和分钟级流程属于教案深化阶段，不在学期框架阶段过度生成。

### 11. 分阶段实施

1. Phase 0：目录不可变版本、统一语义模型、Agent 资源作用域。
2. Phase 1：学期框架和单元/课时规划的最小闭环。
3. Phase 2：连续性候选引擎、Agent 检索与解释、资源补丁审批。
4. Phase 3：学情、练习/错因证据、课堂反馈和后续计划修正。
5. Phase 4：跨教材、跨年级复用、质量治理和规模化知识网络。

### 12. API 边界

提供目录发布版本查询、知识点/关系检索、学期框架 CRUD、单元与课时规划、连续性候选、资源补丁审批等服务。API 必须验证 `auth.user → resource owner → resource → thread/branch/run` 的完整隔离链。

### 13. 代码边界

- `data/curriculum`：可重复生成的教材目录源数据；
- `server/curriculum`：目录版本、语义网络与连续性规则；
- `server/agent`：按资源作用域运行、工具和审批；
- `src/features/notebooks`：备课本及学期框架入口；
- `src/features/lesson-files`：正式教案工作区；
- 新的学期框架界面应作为独立 feature，不塞入教案编辑器内部。

### 14. 测试与评测

覆盖目录发布幂等性和历史可回放、跨用户/资源隔离、知识候选审核、连续性推导证据、Agent 工具协议、资源补丁审批和冲突恢复。评测不仅检查是否调用工具，还必须判断回答是否具体、基于已读取业务事实且真正解决教师问题。

### 15. 验收标准

教师可以少量输入完成学期框架初稿；每条复习/铺垫建议都能回答“依据是什么”；从框架可进入课时蓝图和教案；教师修改不会被 Agent 静默覆盖；目录或语义升级后旧框架仍可重放；刷新、重启、分支和审批不会破坏资源状态。

### 16. 明确不做

- 不先做仅供观赏的知识图谱大屏；
- 不让 AI 未经审核直接污染平台公共知识库；
- 不一次生成整学期完整逐字教案；
- 不把教材目录当成教材正文；
- 不因当前模型或向量服务暂不可用而伪造结果；
- 不以 UI 补丁掩盖版本、隔离或审批事务问题。

## 四、BGE-M3 决策记录

### 当前决定

BGE-M3 向量部署与知识点向量回填暂缓，不阻塞 Phase 0 和学期框架 MVP。

当前阶段优先使用：

1. 目录节点精确匹配；
2. 规范名称、别名和全文/词法检索；
3. 相同知识点的跨章节出现顺序；
4. 已审核的显式知识关系；
5. Agent 对检索结果的业务解释。

没有向量证据时，系统不得把模糊语义相似当成已确认的先修关系。需要语义召回的能力应返回“证据不足/当前不可用”，而不是降级为伪精确结果。

### 重新启动条件

满足任一条件后重新评估 BGE-M3：词法召回明显漏掉同义知识点；开始跨年级或跨教材检索；知识规模使规则候选不可控；或有稳定的本地/私有部署和批量回填方案。部署时必须包含模型版本、向量维度、内容摘要、生成时间和重建机制，不能只保存裸向量。

## 五、当前执行顺序

1. **目录发布版本**：建立不可变 release、教材/节点 revision、原子 current pointer，并让语义发布绑定 release。
2. **学期框架基础模型**：建立 framework、unit plan、lesson blueprint，绑定目录与语义版本。
3. **Agent 资源作用域**：将线程、上下文、运行、审批和版本抽象为 `lesson_file | semester_framework`，保持教案现有行为兼容。
4. **确定性连续性 MVP**：用顺序、同知识点和已审核边形成“复习/铺垫”候选及证据。
5. **最小 UI 闭环（已完成）**：从备课本创建学期框架，查看/编辑单元与课时蓝图，并将课时蓝图带入新建教案。
6. **真实 Agent 与评测（已建立发布门）**：教案与框架均走真实 Agents SDK、真实模型、隔离线程和真实审批事件。评测同时检查工具/状态契约与业务质量，不再把工具调用成功等同于回答有效。
7. **正式教案设计依据（后端保留、默认不写）**：保留独立版本化数据及管理能力；只有教师明确要求保存、纠正、删除或复用结构化依据时，Agent 才开放对应写入工具。
8. **A4 直接写入（当前默认）**：整份重编和局部修改都直接读取当前教案，再以一次普通文档审批更新相关栏目。知识点、复习/铺垫、学生困难和评价证据直接转化为教师可读正文，不要求引用映射。
9. **复杂依据投影（可选兼容能力）**：组合事务和单独投影代码保留给明确的治理需求，不再进入普通备课路径，也不得导致连续审批或阻塞成熟的 A4 内容。
10. **业务有效性评测（已实现，待模型额度恢复后复跑）**：已覆盖正式教案与学期框架，评价资源理解、教师目标完成度、课堂可执行性、教材/证据纪律、一次审批边界和不确定性；工具名、内部参数、UUID、知识点内部编码、校验码及技术重试过程属于硬失败。首轮真实基线为 2/5，后续修复复跑因 DeepSeek 余额不足中断，不得把未复跑写成通过。

## 六、正式教案（A4）升级边界

当前 A4 是固定的语义表格，包含基本信息、教学目标、重点知识、重点难点、教学准备、教学过程、评价练习、作业、板书和反思。它解决的是课堂执行和打印，不应同时承担知识网络存储、证据治理和规划历史。

系统可以保留两层数据，但用户主路径只有一层写入动作：

1. **A4 执行文档层（默认）**：保留教师上课真正需要阅读和编辑的内容。本课关键知识进入“重点知识”，并同时转化为可测目标；复习/铺垫转化为课堂衔接；困难和证据进入重点难点、教学过程和评价。一次对话只生成一次正文确认。
2. **教案设计依据层（可选后台）**：可结构化保存框架、蓝图、教材节点、知识关系、来源和治理信息，但普通教案生成不依赖它。没有结构化记录时，Agent 仍可把已经核验和成熟的教学内容写入 A4。

设计依据数据层不直接暴露为教师需要维护的复杂工作台。A4 只增加课堂执行中高频且有明确语义的“重点知识”一等字段，它已进入校验、分页、编辑、撤销、补丁、版本和导出链路；不为每种内部关系追加零散字段。复习与铺垫仍写进目标、过程和评价等真正会被教师使用的位置。

### v0.6 首刀（2026-08-06）

目标：把上下衔接从「只读候选」推进到「教师取舍可持久 + 课堂反馈可回读」，避免课堂反馈做成孤立记事本。

已落地：

1. `framework_continuity_decisions`：按 fingerprint 持久化采用/排除/撤销，覆盖严格层与词法层；刷新时回填决策。
2. 教学衔接面板支持采用/排除；建教案草稿与蓝图展示优先已采用、忽略已排除。
3. Agent：`read_semester_framework_continuity` 暴露教师取舍；框架/教案可读取课堂反馈（`read_framework_class_feedback` / `read_lesson_class_feedback`）。整份生成主路径中，`read_lesson_design_basis` 会附带同单元前序课堂反馈；`read_lesson_class_feedback` 也保留在 full-rewrite 工具集中作为补读。
4. `lesson_class_feedback`：绑定教案/蓝图/框架，支持观察、练习缺口、错因；蓝图卡片可记录反馈。
5. 衔接效果反馈（`continuity_outcome`）可绑定 fingerprint + 方向 + 有效/偏弱/未落实；`read_framework_class_feedback` 对偏弱/未落实给出同单元下一课时回写建议；框架 Agent 默认提出一次 `propose_semester_framework_patch`，不静默改写。
6. **产品闭环（2026-08-10）**：弱/未落实保存后 API 返回 `writebackSeed`；框架工作区自动切入助手并发送带 `feedbackId` 的【衔接回写】消息；能力路由记入 `continuityWritebackFeedbackId`（`writeMode=explicit`）；审批通过后标记 `writeback_status=applied`，后续待回写建议不再重复出现。迁移 `202608100001`。
