# 06 原生模型决策验证与修正

本轮检查原生 Pi 与实际配置模型的行为；不将确定性工具测试或合成案例称为真实教师验证。

## 已确认的问题

1. **完成规则冲突**。决策任务要求保存候选，但普通教学的证据规则要求在检索为空时执行 `complete_without_change`。该工具一旦完成，又会禁止后续提案。初次真实模型运行因此在调用过 `propose_decision` 后仍以 `decision_proposal_missing` 失败。
2. **上下文遗漏**。`read_decision_context` 原先只读取决策，未返回本课学习观察。真实运行中模型误称没有学习记录，即使测试已经写入了一条合成观察。
3. **来源标识不足**。模型曾自行拼接来源地址和采集日期，并抄漏课时 UUID 的字符。读取工具现在发放简短的当前课时/观察标识，由本轮服务端映射到真实资源 URI、版本与读取时间；未知的应用内来源标识被拒绝。引用原文与合成等级仍由固定材料评测核对，当前没有实现对任意外部 URI 的真实性认证。
4. **候选选项无效**。真实输出曾将 `chosenOptionId` 写成字符串 `"null"`。现在所有状态都要求所选 ID 存在于选项中，或使用 JSON `null`。
5. **合成证据分级错误**。一次运行保留了合成文字，但将等级填成 `first_hand_summary`。策略现在明确要求合成观察为 `synthetic`；评测也会检查。该提示约束不等于完整的服务端来源认证。
6. **过度退让**。模型能识别目标与评价之间的文本错位，却因没有真实学生观察而一概退回“证据不足”。现在区分教案内部设计判断与学生学习效果：前者可提出待审阅假设，后者仍须真实观察支持。

## 修复合同

- 决策任务调用 `complete_without_change` 会收到可恢复错误，要求通过 `propose_decision` 保存 `no_change` 或 `insufficient_evidence` 候选；普通教学任务仍保留原来的无需修改完成方式。
- 决策上下文包含最多 20 条学习观察及截断标识，更多记录沿用 `read_learning_progress` 分页。
- 应用内来源在提案前核对已读原文：逐字摘录应来自单个字段，跨栏拼接要拆成证据卡；教案不能分类为课标、教材或学生作品。服务端绑定来源身份、版本与读取时间；外部材料仍不在这项原文认证范围内。
- 模型适配层把无同名选项时的字面字符串 `"null"` 仅转换为“未选择”。其他非法 ID 返回精确合法选项列表，不猜测教师或模型想选哪一项；领域 API 仍拒绝非法 ID。
- 只有上下文完整读取成功后才开放提案；失败读取不再错误地满足前置条件。
- 原生 Pi 集成测试覆盖“读取 → 尝试无需修改并被拒绝 → 保存证据不足候选”，确认不改写 A4、不会产生教师确认或实施事实。
- 保留静态工具 schema；本轮决策完成约束通过动态策略和执行检查传入。

## 可复现的真实模型冒烟

```bash
npm run eval:decision:smoke
```

需要本地配置的模型。脚本使用独立内存仓储，不写生产数据。每个案例建立独立课时，执行前断言学习证据数量和决策数量。

- `goal_evidence`：检查目标与评价的设计对齐，要求保存有选项、反例、不确定性、预期信号及证伪条件的候选。
- `insufficient_evidence`：没有学习观察时，不能断言任务调整会提高本班学习效果，应保存具体证据缺口。

引用核查只针对本次固定材料：课时 URI、版本、逐字摘录，以及合成观察的来源和等级。无法解析的来源视为失败。格式齐全不再等于来源通过核查。

输出写入操作系统临时目录下 `lessonup-evals/native-decision`，保留时间戳报告和 `latest.json`。报告包含原始任务、教案、合成观察、工具结果摘要与候选，供后续审阅。不要将其中 UUID 或临时地址当作生产数据。

## 盲评工具修正

- 修复 `summarize <packet> <key> <summary> <ratings>...` 的参数顺序；新增子进程端到端测试，确认不会修改配对密钥。
- 要求样本与映射完整对应，每个案例恰有一份 baseline 与一份 treatment。
- `status=reviewed` 仅代表评分覆盖完成；均值方向另以 `higher/lower/equal` 报告，不能据此声称统计或教学上的提升。
- 全部评分为同一常数时，机会校正 kappa 不可估计，返回 `null`。
- 配对标签由协调者保管，样本指纹不认证标签真伪；两位填表者也不自动等于两位独立专业教师。

## 真实模型运行观察

使用同一配置模型和 `low` 思考强度，独立案例曾得到以下通过记录；它们不是连续稳定性或成功率结论：

| 案例 | 保存结果 | 耗时 | 边界 |
| --- | --- | --- | --- |
| 设计对齐 | `proposed` | 47,983 ms | 原文、来源、版本及合成等级核对通过；仍有一次证据置信度遗漏重试 |
| 缺少学生效果证据 | `insufficient_evidence` | 111,864 ms | 来源预检与独立原文核对通过；多次参数重试，不能称为性能达标 |

另外保留了规则冲突、合成等级错误、抄错 UUID、拼接引用、错误来源分类、非法选项、120 秒取消以及请求中断的失败记录。部分中断运行出现约 16 分钟的墙钟跨度，不能作为正常模型延迟样本，也没有被计为通过。

最后检查还发现工具 schema 使用的是业务输出形态，将有默认值的字段也标为必填。决策工具改用输入形态，由 Zod 补齐默认值；原生 Pi 集成测试证明缺省字段可正确处理，其他工具仍使用原合同。该优化后的真实模型重跑发生请求中断，**未验证实际延迟收益**。下一步应在连续、可控环境中测失败率、重试数与端到端分位延迟，而不是重复选取最快的单次记录。

没有生成不公平的前后评分，也未用机器代理冒充独立教师评审。运行报告中的任务、原材料与输出已可用于后续公平对照设计。

## 证据边界

尚未完成真实教师评分或课堂 pilot。本轮没有制造评审资历、用机器评分冒充教师，或把前后修复的不同提示词输出当成公平的 baseline/treatment 质量对照。真实运行报告可作为后续评审原材料；当前主要证明执行路径和固定来源核查，不证明教师留存、备课时间或学生学习效果改善。
