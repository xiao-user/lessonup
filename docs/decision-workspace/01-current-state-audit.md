# 01 现状审计：Agent 流能否推动决策？

- 审计基线：`1056441`（2026-10-18），生产版本 `f15f370a-9922-40e0-9906-bb78d39bda5b`。
- 方法：阅读路由/工具/提示/数据/评测代码与文档；运行本地测试与性能测量；不依赖厂商宣传或模型自述。
- 局限：没有真实教师访谈与课堂观察；性能为单机、4× CPU 场景；模型延迟未在本轮用真实供应商基线测量。

## 2. Agent 流逐项验证

判定标准不是“能否生成教案”，而是能否推动可检查的教学决策。

| 决策支持要求 | 现状 | 证据 | 判定 |
| --- | --- | --- | --- |
| 明确的决策对象 | 提案是“文档补丁/整份编写”，没有“目标取舍、任务序列、支架、评价证据、课后调整”的结构化决策 | `proposal-tools.ts`、`document-patch.ts` | **缺失** |
| 一手证据可追溯 | 工具结果与引用存在，但未形成带定位、版本、适用条件、冲突标记的证据卡 | 工具输出、`education-policy.ts` 要求区分依据 | **部分** |
| 比较替代解释 | 提示词要求比较解释与反例；结果以自由文本呈现，未记录被放弃的选项 | `education-policy.ts` | **部分/不可检查** |
| 不确定性与适用条件 | 提示词明确要求保留不确定性与局限；没有结构化字段，无法聚合或审计 | `education-policy.ts` | **部分/不可检查** |
| 允许“不改” | `complete_without_change` 已落地，且与提案互斥 | `teaching-completion.ts` | **具备** |
| 连接学生学习结果 | 学习证据可选择记录并进入下一轮；默认只读最近 3 个前序课时、每课时 8 条；没有学生级结果模型 | `server/learning/service.ts`、`education-agent-architecture.md` | **局部** |
| 实施保真度与剂量 | 记录“是否实施”，没有课堂观察、fidelity、剂量 | 学习闭环表结构 | **缺失** |
| 决策溯源 | 原始对话与提案可追溯；没有“为什么选这个方案、放弃了什么、置信度多少”的决策记录 | `run-evidence.ts`、审批投影 | **缺失** |
| 专家校准 | 盲评工具与 rubric 存在；当前通过门槛是项目自定规则，未执行外部专家校准，也未报告评审者一致性数据 | [professional-review.md](../professional-review.md) | **未完成** |
| 效果验证 | 明确区分观察/解释/实施/结果；真实课堂证据尚未采集 | 架构与评审文档 | **未完成** |
| 性能/失败预算 | 评测记录 `durationMs/firstOutputMs/modelRequests/toolCalls/inputTokens`；发布阈值需显式配置；UI 性能门默认只记录 | [evals/README.md](../../evals/README.md) | **部分** |

**结论**：当前 Agent 流能“读得对、改得稳、说得谨慎”，但**不能证明决策更好**。它优化的是材料交付效率与可追溯性；决策对象、决策质量、实施保真和学习结果尚未成为一等公民。

## 3. 失败模式（按影响排序）

| ID | 失败模式 | 影响 | 证据 | 严重度 |
| --- | --- | --- | --- | --- |
| F1 | 把“采用提案”当作成功 | 采用 ≠ 决策正确，可能放大错误方案 | 审批与评测以提案/采用为中心 | 高 |
| F2 | 决策不可见 | 教师无法比较选项、理由与反例；无法复盘 | 提案为文档补丁，无决策字段 | 高 |
| F3 | 学习证据局部且有窗口 | 只看最近 3 课 × 8 条，可能遗漏关键反例 | 组合教学上下文 | 高 |
| F4 | 没有学生级结果与保持/迁移 | 无法回答“是否学会”，只能回答“是否完成” | 学习证据表结构 | 高 |
| F5 | 没有实施保真度 | 无法区分方案无效与实施偏离 | 学习闭环只记录“实施时间” | 高 |
| F6 | 评测以模型评分与合成为主 | 可能自证；缺少外部专家一致性与真实课堂 | `eval:agent`、`eval:learning:smoke` | 高 |
| F7 | 评价工具不足 | 无题目难度/区分度/干扰项/评分标准分析 | 无对应数据模型 | 中高 |
| F8 | 学生原始作品未结构化进入 | 学情判断依赖教师转述或模型推断 | 仅附件/资料来源 | 中高 |
| F9 | 教师时间与负荷未测量 | “节省时间”不可验证 | 无遥测 | 中 |
| F10 | 课程/教材版本冲突未作为对象 | 过期引用可能悄悄进入方案 | 资料有版本，决策层未强制核对 | 中 |
| F11 | 模型延迟无真实供应商基线 | 体验承诺不可验证 | 评测只记录，未固化 p50/p95 | 中 |
| F12 | 未成年人数据流未定义 | pilot 前存在合规阻塞 | 当前无学生数据采集流程 | 中（阻断 pilot） |

## 5. 已证明与未证明

**已证明（工程层）**：作用域、版本、审批、幂等、取消/恢复、可编辑性、指定场景性能；工具可被真实模型调用并完成受控任务；系统会在证据不足时允许“不改”。

**未证明**：决策质量高于基线；教师时间下降；实施保真；学生学习改善；专家一致性；长期保持与迁移；真实设备/网络下的 p95。

## 6. 审计结论

1. 现有系统是“材料交付 + 证据记录”的闭环，不是“决策支持”闭环。
2. 最强的资产是：可追溯的一手数据、明确的审批边界、允许不改的诚实机制、已有的评测/盲评基础设施。
3. 最大的缺口是：决策对象与决策质量不可见、实施与结果不连通、内部/模型证据无法替代外部专家与真实课堂。
4. Phase 0 应优先补“决策对象 + 证据卡 + 验证协议 + 埋点”，而不是新增生成能力。

## 7. 开放问题（需评审确认）

- 决策记录是“每课时 3–5 个”还是按单元聚合？粒度如何避免增加教师负担？
- 证据卡是否允许引用教师口述/课堂观察？如何标注可信度与不可复用性？
- 学习结果的最小学生级数据是什么？在合规前提下能否只做班级聚合？
- 现有学习证据表是扩展还是新建决策表？迁移策略与回退方案？
- 内部评审代理的可接受边界是什么？哪些结论必须等外部专家？
