# 07 决策输入合同与可靠性复核

本轮继续检查配置模型和同一原生 Pi 决策链路，范围是来源输入、候选完整性与重试。未改 UI、教师确认/实施/审议权限或生产部署。

## 已修正的合同问题

1. **服务器字段不应先要求模型填写。** 旧工具要求本地来源的 `system/version/capturedAt`，随后又覆盖版本与采集时间；缺字段或无效日期在绑定前就被拒绝。现在模型工具有独立的输入 DTO，本地来源只需 `uri/locator`，先通过已读来源注册表绑定服务器身份与元数据，再经过原有严格业务 schema。外部来源缺少系统、版本或有效日期仍被拒绝，不生成虚构出处。本地系统标识统一为 `lessonup`。
2. **已读旧页观察无法引用。** 决策工具原来只登记最近 20 条观察，却让模型到另一个工具分页；另一个工具不会更新决策来源注册表。现在 `read_decision_context.evidenceBefore` 与 `learning.next` 配套，每页仍最多返回 20 条。只有实际返回的记录才可引用，查询用的第 21 条探测记录不会提前获得来源资格；别名跨页保持稳定。
3. **可行动候选缺项仍落库。** 本轮基线中的正向候选遗漏 `confidence`，业务层仍保存为 `proposed`，而独立评测正确判失败。决策工具现在在保存前一次返回缺少的置信度、反例、假设、不确定性、预期信号及证伪条件；`insufficient_evidence` 与 `no_change` 保留其合法例外。置信度仍是待校准的模型自评，不是统计概率保证。
4. **合成比例不能当真实改进基线。** 基线输出曾用合成的 9/30 比较未来课堂表现。动态策略明确禁止这样设置真实班级的基线、改进幅度或阈值；应说明将来如何采集真实基线，再检查保持与迁移。这是模型行为约束，不能代替专业审阅或自动证明所有推断正确。

5. **来源类别需要由读取结果明确给出。** 首批四例全部先误分教案来源。后续读取结果增加 `lessonSource.kind=platform_data`，工具 schema 与错误反馈明确要求按实际来源分类；不把模型填错的类别静默改成正确值，原拦截继续执行。
6. **字段齐全仍可能比较错误的指标。** 来源提示后的证据不足例虽通过工具检查，其预期信号却把识别正确率与解释达成率相比，不能说明学习改进。动态策略进一步要求前后使用同一目标与成功判据，说明文本难度、提示条件与因果限制；不可比指标分别记录，没有可比基线时先采集真实基线。本问题由内容审阅发现，不能把工具通过解释为教学判断全部正确。

所有来源原文、来源类别、版本、所有权、单次提案与教师权限检查继续执行。业务 API 的证据结构没有放宽；静态工具 schema 不包含本轮 UUID、时间戳或动态枚举。

## 测量协议

- 基线为提交 `b3a979a`，两例各一次；正向例 58,206 ms，因缺置信度失败；证据不足例 48,230 ms，通过。两例都经历一次工具纠正；失败分别为错误来源类别与拼接引文。本批未直接观察到元数据遗漏，元数据问题由本地原生验证复现。
- 修复后在调用模型前固定 `LESSONUP_EVAL_REPETITIONS=2`，两轮共四例，均使用同一配置模型、`low` 思考强度和重建的独立内存仓储。途中不修改运行中的业务代码，不删失败或另选最快样本。
- 报告启动时创建，每例结束落盘；包含计划、已完成、待执行、通过、失败、提案尝试与工具失败数。`complete=false` 的部分报告不能当成完整成功批次。
- 报告和原始合成材料保留在系统暂存目录 `lessonup-evals/native-decision`。重复次数限定 1–5，未知案例 ID 在调用模型前拒绝。原文核查和通过标准没有降低。

```bash
LESSONUP_EVAL_REPETITIONS=2 npm run eval:decision:smoke
```

## 本轮观测结果

以下“通过”仅指指定工具、结构和来源检查；不同阶段修改了合同或提示，不是控制其他变量的因果实验。

| 阶段 | 工具检查通过 | 提案调用 / 工具失败 | 各例耗时（ms） | 内容审阅 |
| --- | --- | --- | --- | --- |
| `b3a979a` 基线，两例 | 1/2 | 4 / 2 | 58,206；48,230 | 正向候选缺置信度；还出现合成比例作比较基线 |
| 输入修复，固定第一轮 | 2/2 | 5 / 3 | 75,868；64,399 | 仍需纠正来源类别与缺项 |
| 输入修复，固定第二轮 | 2/2 | 6 / 4 | 79,214；61,459 | 仍需纠正来源类别等输入问题 |
| 明确来源类别，两例 | 2/2 | 2 / 0 | 45,510；34,073 | 缺证据例的未来建议仍误比识别率与解释率 |
| 增加可比判据约束，仅缺证据例 | 1/1 | 1 / 0 | 24,721 | 明确两种判据要分别取证，保持未选择、未确认，不虚构行动效果或比较方案 |

固定四例未隐藏失败工具调用。来源类别提示后的两例首次提案通过，之后只针对已发现的语义问题单独复核一例，并保留前一版问题输出。最后一例没有填充无依据的行动信号和证伪方案，按 `insufficient_evidence` 的合法合同保留空值，列出真实缺口。不能将这一个 24,721 ms 样本当作产品稳定时延。

本轮输出中，真实基线与合成比例的边界已更明确：例如正向候选提出首次真实实施时建立基线、以后再检查保持与迁移，而不引用合成 9/30 作为改进幅度。对比判据、评分负担与实际适用性仍需教师审阅；这些观察没有被包装成真实学习效果。

## 工程验证

- 全量 Vitest：135 个文件，768 项通过、1 项跳过。
- 最终相关检查：决策工具、原生 Pi 与动态策略 68 项通过，包含本地省略元数据、无效占位覆盖、完整外部出处、旧页引用与探测行拒绝、候选缺项可恢复修复。
- 类型检查、Cloudflare 类型检查、构建与差异检查通过。本轮没有 UI 或编辑器修改。
- 两次独立代码审阅未发现本轮高置信度回归；代码审阅不是教师评审。
- 本轮无部署、无数据库迁移；生产版本仍以发布记录为准。

## 结果边界

少量固定案例及一次基线不能估计稳定成功率或 p95，也不能分离网络、缓存、输出长度和模型抽样对时延的影响。输入合同删除无效失败路径，不等于已测得时延下降；严格拦截原先漏过的缺项也可能增加纠正次数。

通过只表示指定合成案例满足运行、权限、结构与已知材料来源检查。教师负担、专业判断质量和真实教学效果仍需独立验证。例如模型建议两位评分者独立打分，是否值得该教师投入仍需实际备课情境校准，不能因字段齐全就认定方案适用。
